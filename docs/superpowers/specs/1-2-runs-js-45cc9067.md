## Behaviour

### `validateDispatch(form)` -> `{ok, errors}`

`form` has `dispatchDefaults`' keys: `{allowNoVerification, base, parallelism,
prefix, verify}`. Any part may be missing or garbage.

Always returns a fresh object with exactly the keys `errors, ok`:

| key | type | meaning |
|---|---|---|
| `ok` | boolean | `true` exactly when `errors` is empty |
| `errors` | array of `{field, message}` | one entry per failed rule, in the order below; each entry a fresh object with exactly the keys `field, message` |

Rules, checked independently (every failing rule is reported, not just the
first), entries in this order:

1. **prefix** (`field: "prefix"`): an error when `form.prefix` is not a string
   or is blank after trimming (`""`, `"   "`, `"\t\n"`). Any other string,
   including one with inner spaces, passes (see Out of scope).
2. **verify** (`field: "verify"`): count the elements of `form.verify` (when it
   is an array) that are strings with non-blank content after trimming, the same
   test `dispatchDefaults` uses (runs.js:886-888). An error when that count is 0
   **and** `form.allowNoVerification !== true` (exactly `true`; `"true"`, `1`
   do not opt out). Parent line 80-81: verification is required by `am`; the
   opt-out is the explicit checkbox. Commands present with the opt-out also
   ticked is not an error.
3. **parallelism** (`field: "parallelism"`): an error unless
   `form.parallelism` is a whole number >= 1 (`_isWholeNumber` and `>= 1`, the
   same test `dispatchDefaults` applies to the stored value). So `0`, `-1`,
   `2.5`, `NaN`, `Infinity`, `"3"`, `null` and missing are errors.

A garbage `form` (not an object per `_isObject`) is read as `{}`: all three
errors, `ok: false`.

Messages (exact, no trailing period):

| name | field | text |
|---|---|---|
| PREFIX_EMPTY | `prefix` | `Enter a branch prefix` |
| VERIFY_MISSING | `verify` | `Add a verify command or choose to run without verification` |
| PARALLELISM_INVALID | `parallelism` | `Parallelism must be a whole number of at least 1` |

### `previewSummary(dryRunData)` -> `{board, integrate, summary}`

Always returns a fresh object with exactly the keys `board, integrate, summary`
(all three are strings or a boolean, never `null`):

| key | type | meaning |
|---|---|---|
| `board` | boolean | `true` when `dryRunData.board === true` and the payload is readable |
| `summary` | string | the counts line, `""` when unreadable |
| `integrate` | string | the Integrate line for a milestone, else `""` |

Counting rule shared by both variants: **the subtasks of a milestone plan** are
the number of elements that are objects (`_isObject`) in
`stories[].subtasks`, over every `stories` entry that is an object, over every
`levels` entry that is an object; a non-array `levels`, `stories` or
`subtasks` contributes 0. Only the subtasks listed in levels count (what would
be dispatched), never `already_done` entries.

Pluralisation: a count of exactly 1 takes the singular (`level`, `subtask`,
`story`, `milestone`); every other count (0 included) the plural (`levels`,
`subtasks`, `stories`, `milestones`). Counts print as plain decimal integers.

Decision order:

1. `dryRunData` is not an object (`_isObject` false) -> unreadable:
   `{board: false, integrate: "", summary: ""}`.
2. **Board** when `dryRunData.board === true` (exactly; `"true"`, `1` are not):
   - `levels` not an array -> unreadable (as in 1).
   - N = the number of object entries in `levels[].milestones` (non-array
     `milestones` and non-object levels contribute 0).
   - M = the sum, over those N milestones, of the subtasks of `milestone.plan`
     (a non-object `plan` contributes 0).
   - result `{board: true, integrate: "", summary: "<N> milestone(s), <M> subtask(s)"}`,
     the parent's strongest-warning wording (line 168-170). There is no single
     Integrate branch on a board run, so `integrate` is `""`.
3. **Milestone** otherwise:
   - `levels` not an array -> unreadable (as in 1). This also covers the
     `{ok, data}` envelope passed by mistake.
   - L = the number of object entries in `levels`.
   - S = the subtasks of `dryRunData` (the counting rule).
   - D = the number of entries of `already_done` (when an array) that are objects
     with `kind === "story"`. `kind: "subtask"` entries (a done subtask of a
     pending story) and anything else do not count.
   - `summary` = `"<L> level(s) · <S> subtask(s)"`, followed by
     `" · <D> stor(y|ies) already done"` only when D > 0.
     The parent mock-up (line 61) reads `2 levels · 5 subtasks · 3 stories already done`.
   - `integrate` = `"Integrate → " + _textOf(integrate.branch)` when
     `dryRunData.integrate` is an object whose `branch` is a string that is not
     blank after trimming; else `""`. The parent mock-up (line 62) reads
     `Integrate → m3-integrate`.
   - `board` is `false`.

Examples (milestone): L 2, S 5, D 3 -> `2 levels · 5 subtasks · 3 stories already done`;
L 1, S 1, D 1 -> `1 level · 1 subtask · 1 story already done`;
L 1, S 2, D 0 -> `1 level · 2 subtasks`; L 0, S 0, D 4 (everything done) ->
`0 levels · 0 subtasks · 4 stories already done`. Board: N 3, M 7 ->
`3 milestones, 7 subtasks`; N 1, M 1 -> `1 milestone, 1 subtask`;
N 0 -> `0 milestones, 0 subtasks`.
