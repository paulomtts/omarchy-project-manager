# 4.1.1 runs-watch.py: a nudge and cursor source — design

Card: `86c44434` (subtask of story `1b1f4f8b`, 4.1 Nudges). Parent design:
`docs/superpowers/specs/2026-10-06-am-snapshots-cursors-design.md` in the main checkout (untracked
there; cited below as **M4** with line numbers). Fixtures: `tests/fixtures/am/watch-hello.json`
and `watch-events.json`, regenerated by 4.0.2 (`eb5b4db`) from agent-manager 0.2.0.

## Purpose

`core/backend/runs/runs-watch.py` today takes `<project_root> [run_id ...]`, spawns
`am watch --all --follow`, drops the backlog by timestamp, keeps lines of watched runs or runs
whose `run_upsert` names the project root, and prints `{"changed": ["<run id>", ...]}`. With the
new `am` the watch spans every project and carries a global cursor (`gseq`). This card turns the
helper into a pure nudge and cursor source: no project, no run ids, no backlog filter, no
`repo_dir` mapping; it says "run X changed at global seq N" and "the highest gseq seen is N", and
nothing else (M4 §"The watch helper becomes a nudge source", lines 83-99).

## Inherited constraints

- The plugin reads snapshots and treats watch lines as nudges; it never folds events into state
  and never forwards event contents (M4 §"Goal", lines 45-47; lines 95-96).
- `am` is called only as an argv list; `am.db`, journals and the data dir are never read
  (M4 §"Non-goals", lines 58-59).
- argv has no roots and no run ids, an optional `--since-seq N`; spawns
  `am watch --all-projects --follow` (or with `--since-seq N`). `is_backlog`, `same_dir`, the
  watched set and the `repo_dir` mapping are deleted (M4 lines 87-91; card).
- The hello is accepted when `schema` is 1 or higher and the hello has `head`; a hello without
  `head` is `SchemaMismatch`, "the plugin needs the newer am" (M4 lines 92-94, 198; M4
  §"Decisions", lines 273-275: schema stays 2 with additive `head`, `gseq`, `cursor_reset`,
  `store_id`). The printed hello carries `storeId` as well (card; M4 line 260, 4.1.4 consumes it).
- At most one `changed` line per 250 ms window, the highest `gseq` per run; a `{"cursor": N}`
  line, the highest `gseq` seen, with each changed line (M4 lines 95-97; card).
- Keeps the `AmMissing`, `SchemaMismatch`, `CorruptJournal` (name kept: M4 open question 5, lines
  293-296) and `HelperError` envelopes and the quiet exits (M4 lines 98-99). `StoreBusyError` at
  exit 3 is re-emitted as its envelope (M4 §"Errors", line 203; card).
- Lines with an unknown `event` or key are ignored (M4 lines 79-81).
- No dead-run detection from events (M4 line 61). `am logs` consumption unchanged (M4 line 63).
- In M4 the cursor is held in memory by the consumer; persisting it is not this milestone (M4
  line 269). The helper only prints it.
- Test inputs of am output come from `tests/fixtures/am/`, never hand-written; a synthetic edge
  case is labelled `synthetic:` (card). Docstrings and comments state the contract only, no
  narrative (card). `docs/architecture.md` layering holds; `tests/architecture` passes (card;
  M4 §"Where it goes", lines 230-237). Verification: `bash tests/run.sh` green (card).

## Observable behavior

### 1. argv

`runs-watch.py [--since-seq N]`. `USAGE = "usage: runs-watch.py [--since-seq N]"`.

- No arguments: spawns exactly `am watch --all-projects --follow` (argv list, never a shell).
- `--since-seq N`, where `N` is one or more ASCII decimal digits (0 allowed, leading zeros allowed,
  value read as an integer): spawns exactly `am watch --all-projects --follow --since-seq <N>`,
  with `<N>` the integer's decimal text (`007` gives `7`).
- Anything else is a Usage error: `{"ok": false, "error": {"type": "Usage", "message": USAGE}}`,
  exit 2, and `am` is never looked up or spawned. This includes: any positional argument (a
  project root, a run id), `--since-seq` with no value, a value that is not digits (`-1`, `abc`,
  `5.0`, empty string), `--since-seq` given twice, the `--since-seq=5` single-token form, and any
  other flag.
- `am` not on `PATH` (and argv valid): `AmMissing` envelope, `"am is not installed."`, exit 1.

### 2. hello

A stream line that is a JSON object with `"event": "watch"` is a hello. Every hello is checked,
in this order:

1. `schema` must be a JSON integer (not a boolean, not a float, not a string) of 1 or more. Else
   `SchemaMismatch`, message containing `schema <json of the received value>` (`null` when the
   key is missing) and `1 or higher`.
2. `head` must be present and a non-negative JSON integer (not a boolean). Else `SchemaMismatch`
   with a message containing `the plugin needs the newer am`.

The first accepted hello is printed once, at once, as exactly

```json
{"hello": {"schema": N, "am": V, "head": H, "cursorReset": B, "storeId": S}}
```

- `schema`, `head`: the hello's values.
- `am`: the hello's `am` when it is a string, else `""`.
- `cursorReset`: `true` only when the hello's `cursor_reset` is JSON `true`; else `false`
  (missing, `null`, `1`, `"true"` all give `false`).
- `storeId`: the hello's `store_id` when it is a string, else `""`.
- No other key (e.g. `runs_dir`, `event`) is forwarded.

A later hello is checked by the same rules (a failing one is `SchemaMismatch`) but prints nothing
and does not touch a pending batch. On `SchemaMismatch` the pending batch is not printed, `am` is
terminated at once, and the helper exits 1 with that one envelope as its last line.

Event lines that arrive before any hello are handled as usual (rule 3); a stream with no hello
at all still nudges.

### 3. Event lines → nudges

A stream line is a nudge for run `R` at global seq `G` when all hold:

- it parses as a JSON object without an `ok` key and is not a hello;
- `event` is one of the event kinds am 0.2.0 writes: `run_upsert`, `story_upsert`,
  `subtask_upsert`, `phase_upsert`, `attempt_upsert`, `lease_acquired`, `lease_taken_over`,
  `control_requested`, `control_handled`, `claim_conflict`;
- `run_id` is a non-empty string (`R`);
- `gseq` is a JSON integer of 1 or more, not a boolean (`G`).

Every other line is ignored entirely — it contributes to neither the batch nor the cursor: an
unknown `event`, a missing/invalid `run_id` or `gseq`, non-JSON text, a JSON value that is not an
object. Unknown keys on an otherwise valid line change nothing. The line's per-run `seq`, `ts`,
`payload`, `card`, `story`, `phase`, `attempt` and project are never read for output and never
forwarded.

### 4. Batching (trailing-edge debounce, `WINDOW = 0.25` s)

- The first nudge into an empty batch opens a window; nudges until it closes join the batch.
- The batch maps run → the highest `G` among that window's nudges for the run (a lower `G`
  arriving later never lowers it).
- When the window closes the helper prints, in this order and back to back:
  1. `{"changed": [{"run": R, "seq": G}, ...]}` — one entry per run in the batch, never empty,
     no duplicate runs, each entry exactly the keys `run` (string) and `seq` (integer). Entry
     order is the order runs first entered the window; consumers must not rely on it.
  2. `{"cursor": C}` — `C` is the highest `G` of every nudge seen since the helper started
     (never decreases between cursor lines; at least the highest `seq` in the changed line just
     printed).
  Then the batch is cleared.
- At most one changed line per window: a continuous stream yields no more than one changed line
  per 250 ms of elapsed time, and the window still closes on time (it is not extended by new
  nudges).
- When am's stdout ends, a pending batch is printed (changed + cursor) before anything else.
- No changed or cursor line is printed without a nudge; a cursor line never appears alone.

### 5. How am ended

After the stream ends (pending batch already printed):

| am ended with | helper prints | helper exit |
|---|---|---|
| exit 0, no refusal | nothing more | 0 |
| a refusal line (an object with an `ok` key; the last one wins) and exit other than 3 | that envelope, unchanged | 1 |
| a refusal whose `error.type` is `StoreBusyError`, exit 3 | that envelope, unchanged | 1 |
| any other refusal, exit 3 | `CorruptJournal` with the refusal's `error.message` (non-empty string), else am's stderr, else `"am watch refused with exit 3."` | 1 |
| exit 3, no refusal | `CorruptJournal` with am's stripped stderr, else `"am watch exited 3."` | 1 |
| any other non-zero exit, no refusal | `HelperError` with am's stripped stderr, else `"am watch exited <code>."` | 1 |

### 6. Stopping and robustness (unchanged)

- SIGINT, SIGTERM, or a closed stdout end the helper with exit 0, no traceback, and `am` is
  terminated and reaped (killed after 2 s if it ignores SIGTERM).
- Any other unexpected exception ends with one `HelperError` envelope,
  `"The runs watch failed: <reason>"`, exit 1.
- Every stdout line is one JSON object, flushed as it is printed. am's stderr is drained
  continuously so a chatty am never blocks.

### Module docstring (contract)

Rewritten to state, contract only: the synopsis `runs-watch.py [--since-seq N]`; the spawned
command; the four output line kinds (hello with its five keys, changed with `{run, seq}` entries
holding the highest `gseq` per run, cursor, the error envelopes with their types and exits);
which lines are nudges and that everything else is ignored; that event contents are never
forwarded; the exit-0 cases; that only the `am` command is used. The S4 backlog note, the
project-root adoption text and every mention of journal schema "1 or 2" are removed.

### Harness changes

- `FAKE_AM`: drop the `PAST`/`NOW` `ts` stamping (no backlog any more); steps stay
  `{line}` | `{raw}` | `{sleep}`, then stderr and exit; argv still logged to `calls.log`, pid to
  `pid`.
- Drop `WATCHED`-as-argv, `upsert()`, the `proj` directory, the `ts` parameters, `HELLO1`.
- `RUN` = the capture's run id (`20261008T143807Z-63060df3`). `ev(event)` = a copy of the first
  captured line of that event kind. `nth(i)` = a copy of captured line `i` (gseq 358+i).
- `other(run_id, gseq, event=..., **extra)`: `synthetic:` a captured line with its `run_id`,
  `gseq` and/or `event` replaced (MISSING drops a key), extra top-level keys added — the capture
  holds one run only, so every multi-run test needs it.
- `hello(schema=2, ...)` = the capture's `schema_2` line; `hello(1)` = `schema_1` (no `head`);
  `synthetic:` edits for other schema values, a dropped/edited `head`, `am`, `cursor_reset`,
  `store_id`. `HELLO` = the expected output for `schema_2`:
  `{"hello": {"schema": 2, "am": "0.1.0", "head": 1005, "cursorReset": false, "storeId":
  "91b9e8afc25044c385859292bfabfde7"}}`, derived from the fixture, not typed.
- `run_helper(world, args=())`: default argv is empty.
- `changed(lines)`: validates the alternating changed/cursor pairs (each changed line exactly
  `{"changed": [...]}`, entries exactly `{run, seq}`, non-empty, no duplicate run, followed
  directly by exactly `{"cursor": int}`) and returns `[(sorted [(run, seq)], cursor), ...]`.

## Error paths

Summarised from §1, §2, §5, §6: `Usage` (exit 2, am not spawned); `AmMissing` (exit 1);
`SchemaMismatch` for a bad `schema` or a missing/invalid `head` (exit 1, am terminated, no batch
flushed); a `StoreBusyError` refusal or any refusal at a non-3 exit re-emitted unchanged (exit 1);
`CorruptJournal` for any other exit-3 end (exit 1); `HelperError` for other non-zero exits and
unexpected exceptions (exit 1); exit 0 on am exit 0, SIGINT, SIGTERM, closed stdout.
