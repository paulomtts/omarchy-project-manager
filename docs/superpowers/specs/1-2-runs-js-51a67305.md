## Purpose

Step 1 of the Runs-screen dispatch dialog lists the registered projects, each enabled or
disabled with a reason (DFR l.67-79). This card adds the pure domain function that turns the
registry, the reachability probe and the open project's root into those rows:

```
Runs.dispatchProjects(projectRoots, probe, openRoot) -> [{root, name, open, enabled, reason}]
```

Nothing calls it yet. The store (`dispatchProjectRows`, DFR l.193) wires it in a later card.

## Inherited constraints

- Rows are `{root, name, open, enabled, reason}` (DFR l.176-177; card).
- Input `projectRoots` is S6's `[{root, name}]` that App hands the run stores (DFR l.69-70;
  built in `core/stores/App.qml:109` from `p.root_path` / `p.name`).
- Order: the open project first, marked `open`, then by name case-blind, then by root
  (DFR l.70-71; card).
- A root that the probe marks not ok is disabled and carries the probe's reason (DFR l.72-74;
  card). A root missing from the probe is enabled (DFR l.177-178; card).
- The probe is the output of `board-tree.py --probe ROOT ...`:
  `{"ok": true, "projects": [{"root", "ok", "reason"?}]}`, in argv order (DFR l.153-154;
  `core/backend/boards/board-tree.py:63-72`, reasons `not a directory` and `no .brd marker`).
- Non-array or malformed input never throws (card). This matches the module contract in
  `core/domain/runs.js:165-168` ("none throws: garbage becomes the default").
- Tests live in `tests/core/domain/tst_runs.qml` and cover order, open first, ties,
  unreachable disabled, empty registry and garbage input (card; DFR l.245-246).
- `core/domain/runs.js` is `.pragma library` and imports only other `core/domain` files
  (`docs/architecture.md:11`). `tests/architecture` must pass. `bash tests/run.sh` is green.
  Tests come first. Comments state the contract only, with no narrative (card).

## Behaviour

`dispatchProjects(projectRoots, probe, openRoot)` returns a new array of new row objects. It
never mutates its arguments and never throws.

### Rows from `projectRoots`

- A `projectRoots` that is not an array gives `[]`.
- Each entry that is a plain object (not null, not an array) and whose `root` is a string
  gives one row. Any other entry is skipped.
- `root`: the entry's `root` with every trailing `/` removed; a root of only slashes is `/`
  (the same rule as `withProject`, `runs.js:356-372`). An entry whose root is `""` after this
  is skipped.
- `name`: the entry's `name` trimmed, when it is a string and non-empty after trimming.
  Otherwise the root's last `/`-separated segment, or `/` for the root `/` (the `withProject`
  rule).
- Duplicates: when two entries have the same root after trimming, only the first one gives a
  row. Each root therefore appears at most once.

### `open`

- `open` is `true` for the row whose root equals `openRoot` with trailing `/` removed (the
  `filterByProject` comparison, `runs.js:373-389`). It is `false` for every other row.
- An `openRoot` that is not a string, or is `""`, marks no row open. An `openRoot` that is not
  among the rows marks no row open.

### `enabled` and `reason`

- The probe may be given as the helper's whole payload (an object whose `projects` is an
  array) or as that `projects` array itself. Any other `probe` (null, undefined, a string, a
  number, an object with no array `projects`) counts as no probe entries. The payload's own
  `ok` is not read.
- A probe entry counts only when it is a plain object whose `root` is a string. It is matched
  to a row by root, both with trailing `/` removed. When several entries match one row, the
  first one wins.
- A row with a matching entry whose `ok` is exactly `false` is `enabled: false`. Its `reason`
  is the entry's `reason` trimmed, when that is a non-empty string, else `"unreachable"`.
- Every other row is `enabled: true` with `reason: ""`. This covers no matching entry, an
  entry with `ok: true`, and an entry whose `ok` is not a boolean.
- `open` and `enabled` are independent. The open project can be disabled, and it still sorts
  first.

### Order

1. The open row first, if there is one.
2. Then by `name` lower-cased, by plain string comparison (`<`, as `_compareGroups` does,
   `runs.js:392-405`).
3. Then by `root`, by plain string comparison. Roots are distinct, so no two rows tie.

## Tests (all in `tests/core/domain/tst_runs.qml`, `TestCase` "DomainRuns")

Every test is a QML unit test. `dispatchProjects` is a pure function in `.pragma library`
JS, so the domain tier is the right one: no store, process or UI is involved. Each test uses
the file's existing style (`compare` / `verify` with a label). Inputs are synthetic and marked
`// synthetic:` as the neighbouring tests do.

1. **`test_dispatch_projects_order`**: no open project and an empty probe. Names `b`, `A`,
   `c` give the order `A`, `b`, `c` (case-blind). Every row has exactly the keys `root, name,
   open, enabled, reason`, with `open: false`, `enabled: true` and `reason: ""`.
2. **`test_dispatch_projects_open_first`**: the open project, whose name sorts last, comes
   first with `open: true`. The rest are in name order with `open: false`. An `openRoot` with a
   trailing `/` still matches. An `openRoot` that is not registered marks nothing open.
3. **`test_dispatch_projects_ties`**: two rows whose names differ only by case (`Foo` and
   `foo`) are ordered by root. The row `name` keeps its original case.
4. **`test_dispatch_projects_unreachable`**: with the helper payload shape, a root marked
   `{ok: false, reason: "no .brd marker"}` is disabled with that reason. One marked
   `{ok: false}` with no reason is disabled with `"unreachable"`. One marked `ok: true` is
   enabled with `""`. A root absent from the probe is enabled. The same result comes from
   passing the bare `projects` array. A disabled open project is still first. A probe entry
   whose root has a trailing `/` still matches. The first of two entries for one root wins.
5. **`test_dispatch_projects_names`**: a blank or non-string `name` falls back to the root's
   last segment. A root of `/` gets the name `/`. A trailing `/` on a root is removed in the
   row. A padded name is trimmed.
6. **`test_dispatch_projects_empty`**: `[]` with any probe and any `openRoot` gives `[]`.
7. **`test_dispatch_projects_garbage`**: `projectRoots` of `undefined`, `null`, `"x"`, `5`,
   `{}` gives `[]`. An array mixing `null`, `"x"`, `[]`, `{}`, `{root: 5}`, `{root: ""}` and a
   duplicate root keeps only the valid, first-seen rows. `probe` of `undefined`, `null`,
   `"x"`, `5`, `{}`, `{projects: "x"}`, `{ok: false, error: {...}}` and an array of junk
   entries (`null`, `{root: 5, ok: false}`, `{root: "/p/a", ok: "no"}`) leaves every row
   enabled. An `openRoot` of `5`, `{}`, `null` or `""` marks nothing open. Nothing throws, and
   the inputs are unchanged (`JSON.stringify` before and after).

## Error paths

There are none beyond the garbage rules above. The function never throws and never returns
anything but an array.
