# 4.1.2 runs-snapshot.py: --all-projects with as_of_seq and a single-run read — design

Card: `d9ee001c` (subtask of story `1b1f4f8b`, 4.1 Nudges; blocked by 4.1.1 `86c44434`, landed on
this branch at `d89e697..dc61190`). Parent design:
`docs/superpowers/specs/2026-10-06-am-snapshots-cursors-design.md` in the main checkout (untracked
there; cited below as **M4** with line numbers). Fixtures: `tests/fixtures/am/runs.json` and
`status-*.json`, regenerated by 4.0.2 from agent-manager 0.2.0.

## Purpose

`core/backend/runs/runs-snapshot.py` today takes exactly one `<project_root>`, runs
`am runs --repo-dir R`, then `am status <id> --repo-dir R` for every non-terminal run and the
newest 10 terminal ones, and prints `{ok, runs, data_dir}`. With the new `am` a snapshot carries
`as_of_seq` (the global event cursor it reflects) and `store_id`, `am runs` can list every
project at once, and `am status RUN` finds a run by id without `--repo-dir`. This card:

1. makes the default snapshot span every project (`am runs --all-projects --limit N`), with the
   project root demoted to an optional filter;
2. forwards `as_of_seq` and `store_id` in the helper's output, and refuses an `am` that does not
   send `as_of_seq`;
3. adds a single-run read (`--run RUN` → one `am status RUN`) that 4.1.3's refresh-on-nudge uses.

## Inherited constraints

- The plugin reads snapshots and treats watch lines as nudges; it never folds events into state
  (M4 §"Goal", lines 45-47). This helper reads only snapshots (`am runs`, `am status`).
- `am` is called only as an argv list; `am.db`, journals and the data dir layout are never read
  (M4 §"Non-goals", lines 58-59).
- The am interface: `am runs --all-projects [--limit N] [--before RUN]`, each row has
  `project: {id, repo_dir}`, the envelope carries `as_of_seq`; `am status RUN` needs no
  `--repo-dir` and carries `as_of_seq` (M4 lines 73-74). Verified against `am runs --help` /
  `am status --help` of the installed am: neither command takes an `as_of_seq` flag; `as_of_seq`
  and `store_id` are keys of the envelope's `data` (fixtures: `runs.json` data
  `{as_of_seq: 989, runs, store_id}`; `status-done.json` data `{as_of_seq: 1005, control,
  integrity, rows, run, stories, store_id, warnings}`). "Forwarding `as_of_seq`" therefore means
  copying it into this helper's output.
- `runs-snapshot.py` shrinks to `am runs --all-projects --limit N` followed by `am status` per
  selected run, same selection rule (every non-terminal run plus the newest K terminal ones),
  forwarding `as_of_seq`; the per-project `<project_root>` argument becomes an optional filter
  (M4 lines 114-116; M4 line 170-171; card).
- 4.1.3 needs the single-run read for its refresh (M4 line 259, line 269); the store refreshes one
  run through `am status RUN` and the list through `am runs --all-projects --limit` (M4 lines
  104-108, 201).
- `am` too old (`runs` without `as_of_seq`) is `SchemaMismatch`: "the plugin needs the newer am"
  (M4 §"Errors", line 198).
- `am status RUN` refusing (unknown run) is the store's to handle (M4 line 202): the helper only
  passes the refusal through.
- `StoreBusyError` (exit 3): the helper re-emits the envelope (M4 line 203; card "refusal
  passthrough").
- `store_id` is forwarded so 4.1.4 can reset on a store change (M4 line 260; M4 §"Decisions",
  lines 273-275).
- No dead-run detection from events (M4 line 61); `lease` stays on the `am runs` row as today.
  `am logs` consumption unchanged (M4 line 63).
- Test inputs of am output come from `tests/fixtures/am/`, never hand-written; a synthetic edge
  case is labelled `synthetic:` (card). Docstrings and comments state the contract only, no
  narrative (card). `docs/architecture.md` layering holds and `tests/architecture` passes (card;
  M4 §"Where it goes", lines 230-237). Verification: `bash tests/run.sh` green (card).

## Decisions this spec makes (the card and M4 leave them open)

- **D1 — argv disambiguation.** A run id and a project root are both bare strings, so the
  single-run read is a flag: `--run RUN`. The project filter stays positional, so the call
  `RunStore.refresh()` makes today (`snapshotRunner.run([store.project])`,
  `core/stores/RunStore.qml:165`) keeps working unchanged until 4.1.3 rewrites it.
- **D2 — the project filter is applied by `am`, not by the helper.** With `<project_root>` the
  helper calls `am runs --repo-dir R --limit N` (no `--all-projects`): `am` owns the
  project-identity rule (path resolution, symlinks), keeps its `RepoDirError` for a non-repo, and
  applies `--limit` after filtering, so a busy other project cannot push this project's runs out
  of the window. The helper never compares paths.
- **D3 — `am status` never gets `--repo-dir`.** In every mode it is `am status RUN` (M4 line 74).
- **D4 — the list window.** `LIST_LIMIT = 200`, passed as `--limit 200` on every `am runs` call;
  one call, no paging (`--before` is not used: pages would carry different `as_of_seq` values and
  the snapshot must have one). The selection rule is applied to those newest 200 rows; a
  non-terminal run older than the 200th row is not in the snapshot (stated in the docstring).
  `TERMINAL_LIMIT` (K) stays 10; `TERMINAL` stays `done, escalated, stopped, cancelled,
  canceled`.
- **D5 — output keys.** Top-level `as_of_seq` and `store_id` are added to the list output; each
  run's `status` stays am's `status` data verbatim (which carries that call's own `as_of_seq` and
  `store_id`). The single-run output mirrors one list entry's `status`. All additions are
  additive: `RunStore.applySnapshot` reads only `ok` and `runs` (`core/stores/RunStore.qml:496-504`).
- **D6 — `store_id` coercion** matches `runs-watch.py` (`check_hello`): forwarded when a string,
  else `""`. It is never a reason to fail.

## Observable behavior

### 1. argv

`USAGE = "usage: runs-snapshot.py [<project_root> | --run RUN]"`. Three forms:

| argv | mode |
|---|---|
| (none) | **all projects** |
| `<project_root>` — one argument, non-empty, not starting with `-` | **project filter** |
| `--run RUN` — exactly two arguments, `RUN` non-empty and not starting with `-` | **single run** |

Anything else is a Usage error: `{"ok": false, "error": {"type": "Usage", "message": USAGE}}`,
exit 2, and `am` is never looked up or run. This includes: two positional arguments, an empty
string, a lone `--run`, `--run ""`, `--run -x`, `--run=R`, `--run R extra`, `<root> --run R`,
`--run R <root>`, `--run A --run B`, any other flag (`--all-projects`, `--limit`, `-h`).

Arguments are passed to `am` as single argv elements, never through a shell (a root named
`my proj; echo x` arrives intact).

`am` not on `PATH` (argv valid): `AmMissing`, `"am is not installed."`, exit 1.

### 2. List modes (all projects, project filter)

am calls, in order, each an argv list with stdin `/dev/null` and the existing `AM_TIMEOUT` (60 s):

1. all projects: `am runs --all-projects --limit 200`;
   project filter: `am runs --repo-dir <project_root> --limit 200`.
2. For each selected run, in am's (newest-first) order: `am status <id>`.

Selection (unchanged rule): walking the rows in am's order, every row whose `status` is not in
`TERMINAL` is kept; a row whose `status` is in `TERMINAL` (exact, case-sensitive match) is kept
while fewer than 10 terminal rows have been kept. Kept rows keep am's order.

`am runs` data is checked before any `am status` call:

- `data` must be an object with a `runs` list of objects, each with a non-empty string `id` and a
  string `status` (unchanged) — else `AmBadOutput`.
- `data.as_of_seq` must be a non-negative JSON integer (not a boolean, not a float, not a string)
  — else `SchemaMismatch`, message containing `the plugin needs the newer am`.

Each `am status` data is checked:

- an object — else `AmBadOutput` (unchanged);
- `as_of_seq` a non-negative JSON integer — else `SchemaMismatch`, `the plugin needs the newer am`.

Success, exit 0, exactly one line:

```json
{"ok": true, "as_of_seq": A, "store_id": S, "runs": [<entry>, ...], "data_dir": D}
```

- `A`: `am runs` data's `as_of_seq`.
- `S`: `am runs` data's `store_id` when a string, else `""`.
- `<entry>`: the `am runs` row with every key as am printed it (including `project` and
  `lease`), except that its `status` key is replaced by that run's `am status` data,
  verbatim (its own `as_of_seq`, `store_id`, `run`, `rows`, … untouched).
- `D`: unchanged (`XDG_DATA_HOME` when absolute, else `~/.local/share`).
- No other top-level key. An empty list (`runs: []`) is a success with `as_of_seq` still present.

### 3. Single run (`--run RUN`)

One am call: `am status RUN` (no `--repo-dir`, no `am runs` call). Its data is checked as in §2
(object, else `AmBadOutput`; `as_of_seq` non-negative integer, else `SchemaMismatch`).

Success, exit 0, exactly one line:

```json
{"ok": true, "run": "RUN", "as_of_seq": A, "store_id": S, "status": <am status data>, "data_dir": D}
```

- `run`: the argv `RUN`, as given.
- `A`, `S`: the status data's `as_of_seq` and `store_id` (`""` when not a string).
- `status`: the status data verbatim.
- No other top-level key.

### 4. Failures (every mode)

Every path prints exactly one JSON line (`guarded()`, unchanged).

| case | line | exit |
|---|---|---|
| bad argv | `Usage` envelope | 2 |
| am not on PATH | `AmMissing` | 1 |
| any am call prints an `ok:false` envelope (any exit code; e.g. `UnknownRunError` exit 3, `RepoDirError` exit 0, `StoreBusyError` exit 3) | that envelope, unchanged; no further am call | 1 |
| am prints non-JSON, a non-object, an object without `ok: true/false`, or malformed data | `AmBadOutput` naming the am command | 1 |
| `as_of_seq` missing or invalid in `am runs` or any `am status` data | `SchemaMismatch` (`the plugin needs the newer am`); no further am call | 1 |
| any other exception (timeout, unexecutable am) | `HelperError`, `"The runs snapshot failed: <reason>"` | 1 |

In list modes a failing `am status` fails the whole snapshot: no partial result (unchanged).

### Module docstring (contract)

Rewritten to state, contract only: the three argv forms and `USAGE`; the am commands each mode
runs (`--all-projects` / `--repo-dir R`, `--limit 200`, `am status <id>` without `--repo-dir`);
the selection rule over the newest 200 rows and that older non-terminal runs are outside the
window; both success shapes with `as_of_seq` / `store_id`; the error types and exits, including
`SchemaMismatch` for a missing `as_of_seq` and the unchanged passthrough of any `ok:false`
envelope; only `am` commands as argv lists, am's database and layout never read.

def run(world, args=None, drop=(), **extra):
